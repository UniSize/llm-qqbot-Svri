# 人格库

存放人格定义。机器人启动时读取本目录下所有 `*.json`，一个人格一个文件。

## 用法

1. 复制 `_template.json`，改成需要的文件名（例如 `my-persona.json`）。
2. 按「字段」一节填写内容。
3. 重载机器人使其生效（双击项目根目录的 `reload.cmd`，或在控制台点「重载机器人」）；也可以先在对话里发 `/人格` 确认是否已被读取。

文件名以 `_` 开头的文件是模板，**不会出现在选择菜单里**，也不能通过控制台修改或删除，`_template.json`、`_example.json` 可保留作为参考。

## 首次对话的流程

某个聊天（私聊或群）第一次收到消息、且尚未选定人格时，机器人发送带序号的人格列表，回复序号或名字即可选定。选定后该聊天记住这个选择，后续不再询问。

若一条人格文件都没有，机器人退回单人格模式：直接使用 `.env` 的 `SYSTEM_PROMPT`，不弹菜单。

切换人格：

```
/人格          查看列表和当前人格
/人格 2        按序号切换
/人格 某名字    按名字或 id 切换
```

每个人格的上下文相互独立：切换人格即切换到另一段上下文，切回原人格仍可继续原来的对话；`/reset` 只清空当前人格的上下文。人格文件被删除后，原先选中该人格的聊天下一次对话会重新收到选择菜单。

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 唯一标识，用于 `/人格 <id>`；留空取文件名 |
| `name` | 是 | 显示名；也是 `/人格 <名字>` 的匹配依据，并自动并入群聊 `@` 识别名单 |
| `aliases` | 否 | 额外可匹配的名字数组，同样并入 `@` 识别名单 |
| `description` | 否 | 菜单里的一行简介 |
| `systemPrompt` | **是** | 人格正文 |
| `greeting` | 否 | 选中此人格时先回复的一句话 |

JSON 解析失败或缺少 `systemPrompt` 的文件会被跳过，并在日志中给出告警，不影响其它人格。

## `systemPrompt` 的写法

内容越具体，模型表现越稳定。建议覆盖：

- **身份**：是谁、什么背景
- **性格**：认真 / 懒散 / 毒舌 / 温柔等，以及遇到特定话题时的反应
- **称呼**：如何称呼对方
- **语气和长度**：口语还是书面，一般几句、大概多少字
- **口癖或习惯**：让角色更接近原作或设定的表达方式
- **边界**：明确不应做什么，例如「不要每句都写括号动作」

可用的骨架：

```
你是「名字」，身份是……。性格……。
称呼对方为「……」。说话……（语气），一般……句、不超过……字。
（可选）有个习惯是……。
不要……。
```

## 注意

- `systemPrompt` 会在**每次请求时发给 DeepSeek**，不应写入真实姓名、住址、密码等隐私信息。
- 人格正文建议写成一整行。写成多行也能用（程序会自动压成一行），但可读性较差，建议在 JSON 中直接使用单行长字符串。
- 也可以由控制台的「人格」页签新建、编辑、删除人格，或按「作品来源 + 角色名称」生成草稿后再手工修改；生成内容仅为正常向、全年龄的聊天人格设定。
